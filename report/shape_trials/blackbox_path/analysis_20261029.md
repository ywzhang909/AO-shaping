## 1. 结论

| 编号 | 事项 | 性质 | 状态 |
|---|---|---|---|
| D1 | 锚定目标把实测锚点除以 `counts_scale=16`，模型预测却是原生计数率 | 缺陷，会改写优化方向 | **已修**（`radiometry.count_rate` 单一入口 + 回归测试） |
| D2 | `fit.valid()` 用 8-bit 常量 `peak < 250` 判有效行，12-bit 帧整行被丢 | 缺陷，会静默丢数据 | **已修**（按 `full_scale` 派生阈值） |
| F1 | 模型对得上总能量（1.02–1.11 倍），但对不上残余结构（CV 差 2.1–3.3 倍） | 模型能力边界 | **未修**，下一轮的主要工作 |
| F2 | 综合目标以「窗内能量」换「核心平整」：CV 降 6–19%，EE 降 1.8–3.5% | 目标函数取舍 | **未修**，需改验收约束 |

前者在代码里，已修；后者在模型里，下一轮才动得了。

## 2. D1：锚点的单位是模型的 1/16

### 2.1 代码事实

修前的 `validate.py` 两处（实测损失、锚定图）都是这样归一化的：

```python
loss   = objective.evaluate(sampled / (row["exposure_ms"] * counts_scale), ...)
anchor = anchor_frames.mean(0)[xy] / (anchor_row["exposure_ms"] * counts_scale)
```

而前向模型的输出没有除以 `counts_scale`。`counts_scale = 2**(bit_depth-8)`，本轮
`bit_depth=12` ⇒ `counts_scale = 16`。于是同一次采集里，**实测被压到 1/16、模型没有**，
两者在 `anchored_intensity(anchor, candidate, reference)` 相加时不是同一个单位。

### 2.2 单位到底是哪个：两个独立方向都指向"每毫秒计数"

不需要猜，两轮自己的数就能定。

**(a) 实测均值 ÷ 曝光 ≈ 模型预测**（六组全对，比值 0.99–1.11）：

| 轮次 | 形状（种子态） | 实测均值 ÷ 曝光 | 模型预测均值 | 比值 |
|---|---|---|---|---|
| r1 | square | 202.99 | 186.65 | 1.088 |
| r1 | triangle | 358.09 | 326.79 | 1.096 |
| r1 | rectangle | 165.00 | 156.82 | 1.052 |
| r2 | square | 55.73 | 54.59 | 1.021 |
| r2 | triangle | 177.31 | 160.26 | 1.106 |
| r2 | rectangle | 32.80 | 30.80 | 1.065 |

若按修前代码再除 16，比值会落到 15.7–16.9 —— 与摘要里"模型是实测的 16 倍"完全一致，
所以那不是"模型偏亮"，是**归一化多除了一次**。

**(b) 30 多倍曝光差下拟合出的增益几乎不变**：r1 σ=2.0 px、增益 1951.6（曝光 0.119 ms），
r2 σ=0 px、增益 1863.0（曝光 4.320 ms）。曝光差 36 倍而增益只差 4.5% ⇒ 增益是
**与曝光无关的强度→计数率**系数，与 (a) 同向。

### 2.3 后果：CV 项被放大 16 倍，锚点退化成常数偏置

`anchored_intensity` 的实际形状是

```
composite = anchor/16  +  (model_candidate − model_reference)
```

模型的**绝对**预测量级和实测锚点差 16 倍，而被减掉的 `model_reference` 又把直流项抵消，
所以合成图的直流落在锚点/16（≈3.5）而交流落在模型量级。目标函数里的 `cv2` 项是
`std/mean`：**把 mean 除以 16 而 std 不动，等于把 CV 放大 16 倍**。于是"均匀性"这一项
几乎完全由模型预测的结构决定，实测锚点只贡献一个常数偏置——这与"锚定"的定义相反。
`energy` 与 `shape`（Pearson）都是比值，对整体缩放不敏感，因此**受影响的是 CV 项**。

这也说明早期"锚定块其实等于模型块"的说法不准确：锚定块的**验收**读的是实测图，
与这条路径无关，所以 8/9、9/9 的接受结论本身是干净的；被改写的是**候选相位怎么选出来的**。

### 2.4 修复

新增 `radiometry.count_rate(image, row)` 作为唯一归一化入口（只除曝光，不碰 `counts_scale`），
`fit` / `blur` / `validate` / `direction` / `local_response` / `axial` 六处全部改走它，
不再各自写除法。回归测试：`tests/ao_shaping/tools/slm/transfer/test_radiometry_units.py`
（锚点与预测同单位、`counts_scale` 不进归一化、8-bit 与 12-bit 采集给同一速率）。

**口径变更必须记住**：已记录会话的 `loss`（2.2 量级）是旧口径，重算后整体 ×16。
接受/拒绝是实测对实测的配对比较，缩放对所有行一致 —— **对同一批相位重算结论不变**；
但候选相位由被污染的目标函数选出，所以新旧口径在 device-free 复现里选出不同相位，
块级接受计数也不同（见 §8：匹配检查点 3/3 对 3/3，偏移 10 % 的检查点 3/3 对 2/3）。
**跨新旧读数的绝对损失不可直接比**。

## 3. F1：模型对得上能量，对不上结构

r2 的模糊/辐射度量标定（`blur/result.json`，σ=0 px，增益 1863.0）：

| 形状 | 实测/预测相关 | 相对 MSE | CV 实测 | CV 预测 | EE 实测/预测 |
|---|---|---|---|---|---|
| square | 0.697 | 0.400 | 0.678 | 0.271 | 0.363 / 0.351 |
| rectangle | 0.614 | 0.439 | 0.805 | 0.247 | 0.419 / 0.399 |
| triangle | 0.776 | 0.362 | 0.652 | 0.308 | 0.347 / 0.321 |

EE 差 ≤2%，总能量比值 1.02–1.11 —— **能量口径是对的**。但 CV 差 **2.1–3.3 倍**：
模型认为核心区已经很平整，相机看到的是明显起伏。相对 MSE 0.36–0.44 落在同样的地方。
σ 拟合为 0 说明这点残余结构**不是离焦/模糊**，是模型里没有的项（面板静态相差、散斑、衍射残余）。

r1 反过来，正好作对照：σ=2.0 px，相关 0.92–0.94，相对 MSE 0.05–0.07，CV 比 0.95–1.10。
两幅都是散斑时模型"很准"，因为散斑本来就是高对比、易相关的图样。
**所以 r1 的 0.93 相关不能当"模型可用"的证据**，这也是为什么判据必须看
`target_pearson`（像不像目标）而不是实测/预测相关。

## 4. r2 模板块 0/6 与锚定块 9/9 为什么不矛盾

两个方向相反的接受率，读的是两种图：

| | 模板块 | 锚定块 |
|---|---|---|
| baseline / candidate 算什么图 | 模型预测图 | 实测图 |
| r2 结果 | **0/6**，且指标本身变差（+0.27% … +2.93%） | **9/9**，实测损失降 0.65% … 4.40% |

模型预测图的 CV 是 0.27，实测是 0.67。能让**实测**变平整的相位，在**模型图**里会把 CV
推高（模型已经"平"了，再压就是把结构搬到别处），于是在模板块被判"变差"。同一批相位，
两种图像给出相反符号。

这不是"步长过冲"：过冲会表现为大幅变差且方向随机；这里 6 个块**全部**朝同一侧变差，
量级集中在 0.3–2.9%，与"模型图 CV 偏低 → 目标梯度指反"一致。旁证是差分方向相关
只有 0.40–0.59（r1 的 square 仅 0.083）——模型对"该往哪走"的判断只有中等一致性，
F1 说的结构缺失就是它的来源。

**结论：模板块的拒绝是对的，被拒绝的不是步长，是模型。** 在模型补齐细结构之前，
模板块不该作为验收路径。

## 5. F2：综合分用能量换平整

r2 三个形状，终态相对种子（同轮、同曝光）：

| 形状 | CV | EE（窗内） | 目标峰 | `target_pearson` |
|---|---|---|---|---|
| square | 0.674 → 0.604（−10.4%） | 0.3627 → 0.3534（−2.6%） | 991 → 876（−11.6%） | 0.707 → 0.729 |
| triangle | 0.656 → 0.597（−8.9%） | 0.3471 → 0.3392（−1.8%） | 3198 → 2783（−13.0%） | 0.784 → 0.803 |
| rectangle | 0.812 → 0.657（−19.1%） | 0.4174 → 0.4029（−3.5%） | 1170 → 726（−37.9%） | 0.621 → 0.662 |

综合分（`cv2` 1.0 / `energy` 2.0 / `shape` 1.0 / `smooth` 0.001）判 9/9 接受，但按
`planning_20261029.md` 事先写定的"H2：CV 与 EE **同时**不劣化"，EE 三个形状全部下降 ⇒
**H2 未通过**。

物理上这件事自洽：把核心压得更平，能量就摊到固定 441 px 窗之外；综合分里 `energy`
是窗内占比，权重 2.0，却仍抵不过 CV 项在这一量级上的增益。路线两条，下一轮择一：

1. 验收加硬约束：EE 不低于同块基准的 0.98 倍，否则拒绝（改动小，先做）；
2. 目标里把窗内 EE 当等式约束而非罚项（改动大，需重标定权重）。

## 6. D2：`fit.valid()` 的 8-bit 常量

修前 `fit.valid(row)` 直接判 `peak < 250` —— 那是 8-bit 的饱和阈值。本轮探针采集是
Mono8（`uint8`，峰值 30–200），判得住；而 12-bit 采集峰值上到 3416，会被**整行判无效**，
拟合静默少用数据。已改为 `valid(row, full_scale=None)`，阈值是同一饱和比例的
分数版 —— `peak < (250/255) × full_scale`（`full_scale` 缺省 255 时与原判据逐位相同，
所以 Mono8 行为不变；Mono12 行的截止值是 4014.7，`peak=4000` 有效）。

顺带一处**待复核**（本轮不判定谁对）：`fit` 的增益 169.4 与 `blur` 的 1863.0，
按 `counts_scale=16` 换算后是 2704 对 1863（差 1.45 倍）。两者分别在 8-bit 探针与
12-bit 采集上拟合、路径不同；下一轮统一在同一位深上重拟合后再比。

## 7. F3：起始相位

r1（平面）`target_pearson` 0.10–0.24、模型 σ=2.0；r2（GS）0.62–0.78、σ=0。
同曝光重放（`artifacts/live_acquisition_20261029.md`：13 条相位 × 同曝光，114 帧，
饱和 0）确认这个差别不是曝光或本底造成的伪影，是相位本身。

## 8. 无设备复现

`scripts/slm/simulate_transfer_units_20261029.py` 用已知真值的线性相机重放两条路径
（锚点按旧口径除 `counts_scale` / 按新口径只除曝光），把 §2.3 的推论变成可执行的断言
（seed 1029，无设备，单次运行 41 s）：

- **增益一致性**：`count_rate` 下 Mono12/Mono8 增益比 **1.0004**；旧口径
  `/ (exposure × counts_scale)` 下为 **0.0625** = 1/16 —— 精确因子，不是近似。
- **预测量级 / 锚点**（Mono12 核心 ROI）：新 **1.000×**，旧 **15.996×**；检查点带
  +10 % 离焦误差时新 0.918×、旧 14.695×。旧口径把模型差分加到比锚点小 16 倍的基数上，
  正是 §2.3 的 `composite = anchor/16 + (model_candidate − model_reference)`。
- **隐含损失变化**对实测 **−3.26 %**：新 −2.73 %（差 0.53 个百分点，同号）；
  旧 −10.32 %（差 7.1 个百分点）。检查点有缺陷时旧口径**翻号**——预测 +4.93 %，
  实测 −3.26 %。被污染的不是"每块都拒"，而是**预测变化的量级与符号**。
- **块级接受**：匹配检查点 3/3（新）对 3/3（旧）；检查点离焦 ×1.10 时新 3/3、旧 2/3。
- **负结果，必须写下**：现场 r2 的"模板块 0/6 全拒"**没有被复现** —— 匹配检查点下
  旧口径同样 3/3 接受。所以 D1 解释的是**读数被改写、候选相位被选错**，不能单独解释 0/6；
  0/6 的直接机制是 §4 的"模型图 CV 0.27 对实测 0.67 ⇒ 目标梯度指反"，D1 只是把它
  推向更差。修复后仍需实测确认模板块恢复。

结果见同目录 [`sim_units_20261029.md`](sim_units_20261029.md)。
