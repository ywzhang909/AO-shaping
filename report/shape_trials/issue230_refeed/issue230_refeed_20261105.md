## 1. 背景与动机（衔接 issue #229）

#229 硬件深度匹配复测（`hw_depth_matched_20261105.md`）已给出三项结论：

1. 全 harness 口径（`PhysicalForwardFit` + exposure radiometry + 固定 holdout）下，±Zernike 主动变体与随机变体、无适应基线在所有帧预算（n=2–32）下 NRMSE 差异仍在 ±2% 内——**主动选样无可测样本效率收益**；
2. 同口径 hw2f 仿真同样无区分力；
3. twin 与硬件的 NCC 差距（仿真 ~0.97 vs 硬件 ~0.81）证明当前 twin 空间结构不足，**不能作为在线回灌 / 闭环收益的判据**。

由此，issue230 把焦点从"选样"转移到"适应"：**不改变训练池选择**，而是考察相机/光学状态随时间漂移后，是否通过**在线回灌**（把新采集帧累积进训练）恢复验证集预测质量，并与"全量重拟合"（fresh）对比收益上限。

> 这不需要生产闭环，纯离线可判，与 #229 的直接可复测性一致。

## 2. 实验编排（两 pass + 漂移窗）

采集脚本 `scripts/slm/issue230_refeed_probe.py`（默认 plan-only，`--execute` 才碰硬件；复用生产 `transfer/capture.py` 的曝光 / manifest / 安全关闭）。

| 项 | 值 |
|---|---|
| 采集方式 | 两次 pass：`<out>/pass1`（t0）、`<out>/pass2`（漂移窗后） |
| 训练池 | 单模 ±Zernike，嵌套（任意前缀均平衡子集）；`--modes` 默认 Z4–Z11（8 模）、`--amplitudes` 默认 `[0.5]` ⇒ 8 模 × 2 号 = **16 structured train**，同池用于两 pass |
| holdout | 6 帧随机族相位（**族外**、训练系未见，保证外推）；两 pass 同一 seed 重导出 ⇒ 相同 holdout |
| 漂移窗 | `--gap-seconds`（默认 0；计划 >0，如 60 s，热/力漂移窗口） |
| pass2 几何 | 沿用 pass1 的相机窗口 / 矩阵 / 质心，**无标定行**（漂移测的是 phase→image 响应，几何刻意固定） |
| 配对 | 行标签 `p{0,1}_ztrain_NNN_Zj_amp`，离线按 phase 标识（剥 pass 前缀 `pair_key`）配对 |
| 默认输出 | `<out>/pass1`、`<out>/pass2`、`<out>/probe_plan.json`；`--out` 须全新空目录（`exist_ok=False`） |

## 3. 离线三模型定义与判据

离线脚本 `data/debug/issue230_refeed/analysis/_refeed_models.py`（复用 #229 harness `fit_arm`，import 并按 pass 目录重指向其 `BASE`；只读，不碰硬件）。

| 模型 | 训练集 | 评估集 | 语义 |
|---|---|---|---|
| `stale` | pass1 train[:n] | pass2 holdout | 仅 pass1，从不再拟合 → 度量漂移损失 |
| `stale_p1holdout` | pass1 train[:n] | pass1 holdout | 漂移参考：自身 pass1 基线 |
| `refeed` | pass1 train[:n] **+** pass2 train[:n] | pass2 holdout | 在线回灌（累积），能否恢复 |
| `fresh` | pass2 train[:n] | pass2 holdout | 全重拟合上界 |

每 budget `n` 独立拟合四模型；`refeed` 将两 pass 行**按 phase 配对**并 concatenate。

**导出量**：
- 漂移损失 = `stale_p1holdout` NRMSE − `stale` NRMSE（pass2 holdout）；
- refeed 收益 = `stale` NRMSE − `refeed` NRMSE；
- 上界 = `fresh` NRMSE。

**判据**：若存在漂移且 `refeed` NRMSE < `stale` NRMSE、且 `refeed` ≤ `fresh` 上限，则在在线回灌提升验证集 NRMSE（可解释为：累积新帧比让旧模型穿漂移更优，且不回退到比全重拟合更差）。

## 4. 计划中的分析口径（#229 harness 参数）

`fit_arm` 口径与 `_harness_task2_run02.py` 完全一致（`_refeed_models` 直接 import 复用）：

| 参数 | 值 |
|---|---|
| 模型 | `PhysicalForwardFit`：Z4 defocus + 残差 Z5–Z11，`learn_residual=True`，`learn_amplitude=False`，`focus_diopter=0.0` |
| 分阶 | low 优先 Z4–Z8，再 mid Z9–Z11（`MODE_ORDER`=[4,8)，`MID_ORDER`=[9,12)） |

| 光轴截距 | 固化到实测 reference spot（`fit.origin` 冻结） |
| 辐射度 | `fit_radiometry`，`mode="exposure"`（counts/ms，gain/background/bias 逐帧）；eval 参考 = exposure 归一化 CCD counts |
| 网格 | phase `GRID=128`，`FFT=256`，`pixel_samples=1` |
| 相机窗 | 半跨度 `SPAN=160` px，`WINDOW=320` px |
| CCD PSF | `SIGMA_CCD_PX=8.0`（离线标定，26 px 对称核），生产同款 blaze kernel 对预测与真值一致施加（`conv2d` padding=12，mode constant cval 0） |
| 损失 | L1 + NCC（`loss_and_ncc`），用 blur kernel 参数化 |
| 训练自申报 | `CCD_SCALE=100.0` 电子/计数（名义，与 #229 仿真共用） |
| 预算 | 脚本默认 `BUDGETS=[2,4,8,16]`；`TOPK=32` 为拟合器可考虑的训练池上限 |

## 6. 风险与局限

| 项 | 说明 |
|---|---|
| fixed gain 未标定绝对 counts | 评估用 exposure 归一化 counts 与 `CCD_SCALE=100.0` 名义电子/计数，不经物理绝对标定；比较的是相对 NRMSE，绝对量不具物理电子数语义 |
| 两 pass 需同光学状态 | pass2 沿用 pass1 几何（窗/矩阵/质心），几何刻意固定；若其间光束或面板发生非漂移性跳变，会被误判为漂移损失 |
| 漂移窗大小选择 | `--gap-seconds` 决定暴露的漂移量；过小可能无漂移（refeed 与 fresh 均无收益可展），过大则漂移主导、体系外推失真。实跑应扫一档（如 60 s）验证线性漂移假设 |
| 训练池仅 16 帧 | `BUDGETS` 上限 16（脚本默认），`TOPK=32` 为拟合器考虑上限但两 pass 同意 phase 配对池只有 16；预算刻度较 #229 的 2–32 更粗 |
| 单模振幅单一 | `--amplitudes` 默认仅 `0.5` rad 一档，激励深度未扫；若幅值过小可能区分力不足（参考 #229 深度混杂教训） |
| 配对依赖标签解析 | 配对靠 `pair_key`（剥 `p{0,1}_` 前缀）；标签异常会静默失配，脚本有 `common` 断言，但 holdout 相位相等仅靠同 seed 重导出，无显式校验 |
