## 1. 结论一句话

只落地**一项**：对数强度梯度差分项（`log_gradient_difference_metric`），
以 `--w_loggrad` **修饰**现有目标函数（不改目标族）。其余 5 类**不实现**，理由分三类：
**早已存在**（2 类，扩展即可）、**在本台架退化/冗余**（3 类，有实测数字）。

## 2. 为什么不新增目标族，而是做成修饰项

新增一个 `--objective` 名字要同步改 7 处：`SHAPING_OBJECTIVE_CHOICES`、
`GUARDED/SHAPE_AWARE/ROI_ONLY/DEFAULT` 四个集合、`raw()` 分派、
**两个**wfless 模块的 `objective_mode` 极性元组、以及
`utils/io/file.py::_DATA_MODE_OBJECTIVE_KEYS`（被 `test_objective_spec.py` 子集断言）。
且**极性不会自动生效**：`raw()` 返回原生极性，`sign` 只在下游应用，
新名字会静默落进 `else "min"` 分支。

做成 `w_loggrad` 权重只需 2 处（`ObjectiveParamsPib` + `ShapingObjectiveParams`），
默认 0.0 ⇒ 逐字节不变。极性由已在的 `_sign` 属性统一给出，**不新增极性副本**。

## 3. 落地项：为什么是「对数强度 + 梯度」

原始梯度（Sobel）MSE 在本台架是**陷阱**：差分带噪帧等于去匹配噪声实现，
而噪声每轮重绘 ⇒ 往无梯度 SPGD 的估计里灌纯方差。对数强度同时解决两件事——
对 shot 噪声方差稳定，且对乘性增益不变（真实误差模式是「功率掉了而背景本底不动」）。

**ε 下限是承重件，不是装饰**：PIB 路径把**原始帧**直接送进目标
（无中位数扣除、无 clip），sim 台架实测 **49.85% 像素为负**（51046/102400，
min=-2.128、max=99.24、float64），朴素 `np.log` 产生 **51046 个 NaN**。
故显式用 `1e-8`，**不用** `np.finfo(float64).eps`（2.2e-16 → log 跳变约 36）。

实测性质：

| 性质 | 实测值 |
|---|---|
| 乘性增益不变性 | 增益 1e-6…1e6，最大绝对偏差 **0.000e+00** |
| 与参考结构完全一致 | `0.0000` |
| 负像素帧 | 有限，`0.197`，落在 `[0,1]` |
| σ 单调性 | 1.0 → 0.086 → 0.044 → 0.034（σ=0/1/2/4） |

### 3.1 参考帧为什么**不是**目标形状（实测否决）

原计划拿「目标形状图」当参考。**实测该方案是反向的**：
`create_target_shape("circle", ...)` 返回**二值**圆盘（只有 2 个取值），
`log` 后是阶跃函数，于是该项退化成「半径 R 处有没有硬边」：

| 参考 | 干净高斯斑（应低） | 散斑（应高） | 偏尺寸 | 偏心 | 区分度 |
|---|---|---|---|---|---|
| 二值圆盘（原方案） | 0.4382 | **0.4247** ← 比干净斑还低 | 0.2744 | 0.3964 | 0.164 |
| 平滑高斯剖面 | **0.0000** | 0.0837 | 0.2787 | 0.1874 | **0.279** |

二值参考**排序颠倒**，且没有任何 ε 能修好（背景被压成 `log(ε)` 平台，
唯一结构是裁剪边界处的阶跃）。故参考帧改为**平场捕获**（台架自身*可实现*的剖面）：
匹配剖面恰好 `0.0`，散斑 `0.084`，偏尺寸 `0.279`。

于是该项的语义是「**是否长出了比自然剖面更细的结构**（散斑），
即能量-in-bucket 类目标看不见的那部分」；**形状仍由 `pib`/`shape`/`roi_pib` 负责**。

### 3.2 结构与安全修复（实现中发现）

- **目标式恒等**：subagent 把 `raw()` 改名 `_raw_base` 却没留包装，而
  `__call__` 仍调 `self.raw(img)` ⇒ 目标函数每次调用抛 `AttributeError`，
  整条 PIB 路径失效。已有 26 个测试全绿，因为没有一个调 `__call__`。
- **单个 NaN 像素会中断优化**：原实现对非有限值 `raise`，但非有限帧是预期工况
  （仓库已有三处 `np.where(isfinite, f, 0.0)` 预处理），而该项每轮调用一次 ⇒
  一个坏像素会杀掉数小时 run 且 SLM 停在任意相位。改为按仓库既有约定消毒。
- **`eps` 是死参数**：docstring 说「log 变换下限」，实现却硬编码 `LOGGRAD_EPS`。
  现已生效：`eps=1e-12/1e-8/1e-4` → `0.099/0.086/0.045`。
- **能量门必须结构性地压过修饰项**：`__call__` 直调 `_raw_base`，
  门触发路径**跳过**修饰项，故任意 `w_loggrad` 下 `GUARD_PENALTY=1e3` 都成立，
  而非仅在 `w_loggrad < 1e3` 时。
- **变异测试**：去掉 `__call__` 的 `sign` → 极性测试红；只去掉 `raw()` 的 `sign`
  → 全部仍绿，说明覆盖有洞，已补 `raw()` 级极性断言（补后两种变异都能抓到）。
- **缓存参考场**：参考帧固定，不该每轮重做模糊+对数。拆成
  `log_gradient_field()`（可缓存的单帧半）与
  `log_gradient_difference_from_fields()`（纯比较），实测**每次调用快 2.00×**
  且数值等价（<1e-12）。
- **既有缺陷：`Recorder.__getitem__` 越界抛 `AssertionError` 而非 `IndexError`**
  （`utils/io/file.py`）。Python 的迭代协议靠 `IndexError` 终止，
  `for row in recorder` 因此会一路越界炸在裸 `AssertionError` 上（本轮写门控测试时
  才暴露）；且 `python -O` 会把 `assert` 整条去掉。已改为抛 `IndexError`，
  并顺带支持负索引。

## 4. 被否决的候选（附否决依据）

| 候选 | 处置 | 依据 |
|---|---|---|
| **SSIM** | ❌ 否决 | 平滑光斑上多数 11×11 窗局部平坦 ⇒ 对比度与结构项同时 →1，与斑高/宽无关；50px ROI 下约 70–90% 窗是平的，退化成「方差加权边缘相关」= 归一化互相关的冗余重写。且 SSIM 的不变性是**全局仿射**（y=ax+b），而真实误差模式「功率掉而本底不动」不是全局仿射 ⇒ 恰好是**错的**不变性；还可用模糊换高分。仓库已有 `pearson`（= NCC），正是文献推荐的替代。 |
| **SLM 相位 TV / L1 正则** | ❌ 否决 | `n_max=9` 只有约 45–90 个低阶 Zernike 模式，**本身已是极强平滑先验**，TV 只能去掉这些光滑模式表达不出的泄漏，预期收益 ≈ 0。（相位未包裹，2π 歧义不成立；若真要用应选各向异性 L1-TV。） |
| **朴素加权 MSE** | ❌ 否决 | 仓库已量化：峰值归一 MSE 是 `O(0.003)`，物理项是 `O(1)`，`w_mse=1.0` 只贡献「约 0.2% 的梯度，无法锚定任何东西」（`src/ml/zernike/losses.py:439-442`）。仓库自己的答案是 `poisson_nll`（同文件 `:392`）。 |
| **峰值强度惩罚** | ✅ 已存在 | `shape_metric` 的 `pk_term`（`metrics.py:497`），有界 `(peak-1)/(peak+1)`，默认 `w_peak=0.5`；方形路径另有 `square_peak_to_background_ratio` + `w_pbr`。 |
| **能量守恒** | ✅ 部分已存在 | `roi_energy_loss`（`metrics.py:159`）+ `rms_pib` 第三项 + `max_roi_energy_loss` 门。注意它是**单侧 ROI 亏空**，非真正的总功率守恒约束。 |
| **物理前向模型残差** | ⏸ 不放叶子层 | 存在但都是 torch 且在 `utils/` 之外（`ml/zernike/models.py::ZernikeAmpModel`）。叶子层禁 torch（`test_target_package.py:122-128`）；若要做只能由 optimizer **注入**依赖。 |

### 4.1 峰值安全：已实现为**可行性门**（不是投影，也不是软惩罚）

> 2026-10-07 落地。CLI `--max_peak`（相机计数，默认 `0` = 关闭）。

文献结论与本台架相符：软惩罚存在**交叉问题**——性能项涨 0.2 时，惩罚项涨 3 个单位
仍可能被接受，即 run 会安心停在 3× MPE 处。软惩罚还把无量纲图像指标与物理单位
用一个无法标定的常数耦合起来，且 SPGD 梯度幅度随曝光/增益漂移，
按上周噪声标定的权重会变成潜在违规。

**⚠️ 它不是投影，也不是安全联锁。** 精确语义：

- 每轮 SPGD 必须把 `+d`、`-d` 两个相位**打到 SLM 上**才能估梯度，
  这些帧**在被检查之前就已经出光**，无法召回；
- 被检查的是**刚刚测量的帧**（`c ± d`），而真正被提交的系数 `c − update`
  要到**下一轮**才显示 ⇒ 检测至少滞后一轮；
- 它是**邻域可行性滤波**（「当前探索区域已经超限，不再往里走」），
  不是到可行集的精确投影；
- `_apply_best_on_exit` 重新下发 `best_c` 时不再复核；
- 值是**当前曝光下的相机窗内计数**：`cam_size` 250–320px 窗外的真实峰值不受约束；
  且 `exposure_time_ms == 0` 时自动曝光会降曝光使计数下降而光功率不变，
  从而**掩盖**真实超功率 ⇒ 运行器在该组合下**显式告警**。

**设计取向：镜像 fold 门，而非 noise 门。** 违规时**完全不调用** `optimizer.update`
——noise 门调 `update(zeros)` 是因为那个 diff *本身就是*梯度噪声；峰值违规不含
任何梯度信息，做同样的调用等于用无据的编辑污染 Adam 动量。也不追加 `_diff_history`
（会抬高 `sigma_hat` 让 noise 门过度触发）、不刷新 fold 基线、不 best-track。
完全正交：任何状态都不变。违规轮照样诚实记录（真实 mean J、真实 peak、`diff=0.0`、
`gate="peak"`），并在收尾日志里从 "updates applied" 中扣除。

默认 `0`（关闭）⇒ 现有 run 逐字节不变；v1 只做**硬拒绝**，不做回溯
（回溯能测量真正待提交的点，但要为每次违规付一次 SLM+相机周期，
且治不了主要失效模式——工作点/曝光漂移，那时只有冻结+人工介入有效）。
先用 `gate="peak"` 计数与遥测判断是否值得上回溯。

**真正的人眼/激光安全必须走带外监督/硬件联锁**（IEC 60825-1 MPE），
本门只是 run 完整性保护。
