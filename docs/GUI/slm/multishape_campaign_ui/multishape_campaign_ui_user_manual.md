# 多形状整形 campaign UI (multishape_campaign_ui.py) — 用户手册

## 1. 概述

`multishape_campaign_ui.py` 是「多形状整形 campaign」的操作台：把
`report/shape_trials/multishape_scale/multishape_scale_live_20261028.md` §3.2 那次实验
（4 形状 × 4 阶段 = 16 段 / 112 块）从"逐条 lane 手敲 PowerShell"变成**只选形状与尺寸**。

页面的取舍：

- **你只需要决定两件事**：跑哪几个形状、目标边长多少。
- **其余参数由自动辅助层派生**，表里逐行标出这个值是**实测 / 派生 / 默认 / 手工**哪一类、
  为什么是这个值。你没改过的值不标"手工"。
- **无设备也能先看一眼**：参数表、计划矩阵、时间与磁盘预算、检查卡、历史复盘都不需要
  连 SLM。只有点「开始」需要设备。

```bash
streamlit run src/ao_shaping/gui/slm/multishape_campaign_ui.py
```

## 2. 一次 campaign 的操作顺序

页面从上到下就是七步。

### 2.1 ① 目标（唯一必填）

- **形状**：正方形 / 三角形 / 五角星 / 圆形，多选。默认四种全选（= 16 段）。
  长方形不在 campaign 里（`rectangle` 从未跑过 campaign），所以不提供。
- **边长**：`1200` / `600` / `200` px 预设，"其他"可自填。

一个形状都不选时，②–⑥ 不显示，只剩 ⑦ —— 此时页面仍是一个历史复盘工具。

### 2.2 ② 自动辅助设置

一张参数表：**参数 / 值 / 来源 / 说明**。来源徽标的含义：

| 徽标 | 含义 | 你怎么对待 |
|---|---|---|
| 实测（绿） | 本会话实测，如零级位置、曝光 | 别覆盖；它比任何默认值可信 |
| 派生（蓝） | 由「形状 + 尺寸」或报告口径推出来，如采样窗半跨 | 一般别动；动了要能说出理由 |
| 默认（灰） | runner 的 CLI 默认 | 只在知道后果时改 |
| 手工（黄） | 你改过；说明里记着被替换掉的原值 | 复盘时先看这几行 |

值得手改的只有三个：采样窗半跨 `window_span`、载波周期 `period`、探针采样网格
`capture_grid`。改完表格立刻标黄，并按页面的推导规则重算下游值。

**「按尺寸重新推导（清空全部手工覆盖）」** 把你改过的全部扔掉，表回到全派生状态。
换尺寸之后先按一下它，比逐个改回去可靠。

### 2.3 ③ 计划预览

- 矩阵表：形状 × 阶段 → 块数 / 位深 / updates；默认合计 **16 段 / 112 块**。
- 时间估算："整形墙钟 ≈N min（低–高）"。口径是 `块数 × 24 s/块` 加每阶段静态基线，
  **capture（当前光路采集）、fit（物理预测模型拟合）、重放都不计入** —— 首次跑一个
  新光路要在这之外另外留时间。
- 磁盘估算：每段固定产物量累加，含区间。
- 落盘目录在"落盘目录（--out）"展开项里。默认是
  `data/debug/slm_transfer/multishape_<YYYYMMDD_HHMM>/s<边长>`；
  **换尺寸会自动换目录**（避免跑 s200 时把上一档 s1200 的产物盖掉）。

### 2.4 ④ 模型目录（自动匹配）

下拉列出本机候选的物理预测模型目录，默认选**最新**一份；第 0 项是"从零训练"。
也可以手填路径。

- 有可复用模型 → 跳过 capture/fit，省掉最贵的两段，但**要求光路还是拟合那份模型时的光路**。
- 从零训练 → 每换一次光路都要重来一遍采集与拟合。

### 2.5 ⑤ 运行前检查

六项，每项给状态 + 判据 + 出处，你可以自己复核：

| 检查 | 它在问什么 |
|---|---|
| 几何自洽 | 零级剔除圆盘压进目标方框多少（占目标面积），以及目标框放不放得进采样窗 |
| 磁盘预算 | 计划产物会不会把盘写满 |
| 时间预算 | 是否超过设备占用预算（缺省 8 h，超了只警告）。**优先按历史实测成本外推**，没有实测才回落到"块数 × 24 s"的常数估算 |
| 模型新鲜度 | 你选的模型是不是这次光路该用的 |
| 饱和预估 | 历史 campaign 的 `峰值 / full_scale`，这一档尺寸会不会一开跑就饱和 |
| 曝光收敛史 | 历史 campaign 的曝光阶梯收没收敛 |

规则：

- **红（stop）= 硬停**，不能点开始。
- **黄（warn / unknown）= 需要你逐条勾选**才能开跑。`unknown` 表示**当前信息不足**，
  不是"通过"——没测过就是没测过。
- 三档几何锚点（与报告 §3.2 同口径，零级剔除圆盘半径 60 px）：
  s1200 → 0.79 %、s600 → 3.14 %、s200 → 5.61 %。超过 5 % 起提醒，超过 15 % 停。
- **时间预算那句话要分清"实测"与"常数"**：判据开头写「按实测：约 47 min（依据：2 段实测，
  每块 25.0 s）」是拿历史 campaign 的 `cost.json` 外推；写「常数估算：…」说明没有任何同规模实测
  可比，退回 24 s/块。两者都在时同时给出并标差异百分比（如「差 +4 %，实测更慢」），
  所以「这个形状从没跑过」在卡片上是能直接看出来的，不用猜。

检查卡**不开相机**：它不实现"现场看有没有光"，那要活相机。真正的光路判定在开跑后由
runner 给出（见 §4）。

### 2.6 ⑥ 运行 / 逐块进度

「开始 campaign」同时要求：无红停项、黄项勾完、已连接 SLM、设备没被别的运算占用
（`bench_busy`）、本页没有另一份在跑。禁用时页面会逐条写出原因。

开跑后四块信息：

1. **总进度条**：`块 done/112 · 段 done/16`。分母是**计划**，不是目录里已读到的段数，
   所以跑到一半不会显示成"16/16 完成"。
2. **段状态表**：每段一行，含段首/段末 CV、核心峰值、曝光。`complete` 与 `reused`
   （续跑跳过）算完成；`stopped` 原样显示。
3. **当前段**：一行摘要 + 一张逐块表（块号 / CV / 饱和 px / 核心峰值 / 曝光 / 验收 / 说明）。
4. **轨迹 / 成本 / 段间暂停**（同一段下面三小块）：
   - **逐块 CV 轨迹**：横轴是「段序·块序」，每个形状从 0 起按**计划**块数连续编号，
     段与段之间不重新从 0 数 —— 整轮只有一条连续曲线。
   - **成本**：历史各段的实测秒数 / 块数 / 每块秒数，加一行按本次计划块数的估算。
     从没跑过的形状显示「首次运行，无历史成本」，而不是印一张全 0 的表。
   - **段间暂停**：「在本段结束后暂停」写一个暂停请求文件，本段跑完就停（单块是原子事务，
     停不在块中间）。请求留在目录里没被消费时，下一次「开始」会在第一段跑完后停下；
     面板会把这件事指出来，可以直接「取消暂停请求」。

怎么读这张表（报告 §3.2 的口径）：

- **CV 必须带曝光与饱和一起读**。CV 变好而曝光同时变了，很可能只是更亮的图。
- **核心峰值是目标核心内的峰值**，看整形质量用它；**段内峰值**（全帧最大）看饱和余量，
  要和 `full_scale` 比。两者不是一回事。
- **验收**列是 A–B–B–A 的接受判定（来自该块的 `summary.json`）；空着表示这一块还没下判定。

### 2.7 停止与续跑

页面上有**三个不同的"停"**，别点错：

- **立即停止（当前块结束后）**：单块 24–40 s 是原子事务，停不下来在块中间。点了之后当前块
  跑完就停，journal 记 `stopped`。
- **在本段结束后暂停**：不打断当前形状，等这一段（该形状的这一阶段）跑完再停，
  给的是"把手上这个形状做完再收工"的选项。实现上是一个暂停请求文件，见 §2.6 第 4 块。
- **取消暂停请求**：请求发出去但还没到段边界时撤回；请求已经被消费则无效果。

- **从断点续跑**：只有输出目录里已有 `journal.json` 时才出现，默认勾上，并列出这次会
  跳过哪些段（`complete` / `reused` 才算，`stopped` 不算）。
  - 勾上 → 落 `--resume`，已完成的段不再进段、journal 记 `reused`。
  - **取消勾选只适用于换一个新的 `--out`**。同一个目录不勾 `--resume` 会在已存在的段目录
    上抛 `FileExistsError` —— 那不是"重跑一遍"的意思。

## 3. ⑦ 历史会话

这一节回答两个不同的问题，先看「跑到第几块」，再看「这条光路的模型还能不能复用」。

**逐段 / 逐块复盘**：下拉选一个 campaign 目录（默认第一个），用同一套表离线复盘 ——
不需要设备、不需要开跑。被删掉或挪走的目录会让下拉项失效，页面会自动清掉选择。

**模型复用**（排在复盘读数之后）：

1. **当前光路指纹卡**：先读该目录的 `frozen_parameters.json`；没有指纹文件就按目录产物
   **现场重算一次**（只读：不写盘、不改文件时间）。指纹每一格都是实测值，缺的格子写
   「未记录」—— 不填 0，也不猜。卡片下方一行写清它用来比什么：**窗口、零级位置、曝光、
   相机格式一致才可比**。
2. **候选清单**：从检查点索引列历史检查点，可按形状过滤。有当前指纹时每个候选带
   **兼容分数**与一句三档结论：
   - **推荐**（≥ 0.80）：可以直接应用；
   - **谨慎**（≥ 0.60）：能用，但要你核对差异后再应用；
   - **不推荐**（< 0.60）：低于可用下限，仍可手选，但每个都标了原因。

   这三档的阈值和措辞只有一份实现，页面不自己算分数、也不自己判档。
3. **展开候选**可以看到它自己的指纹与 provenance（哪次运行、哪个阶段产物），并「选用该会话」；
   索引里判 `stale` 的候选带「已过期」角标。
4. **没有指纹的旧检查点**（早于指纹功能）只按路径核对，不会被假装打分 —— 这类候选显示
   「兼容 —」，而不是 0.00。

## 4. 光路无光怎么办

跑着跑着页面出现「光路无光（退出码 3）」横幅，那是**实验系统上的预期状态，不是缺陷**。
横幅里有退出码、`reason`、`cause`，以及一段 `report()` 原文（曝光阶梯的实测数字）。
按 `cause` 分两种，处置方向相反：

| cause | 现象 | 先做什么 |
|---|---|---|
| `blocked` | 峰值不随曝光上升 | **先去看光路**：挡光 / 激光未出光 / 光路漂走了。加曝光补不回来 |
| `exposure_ceiling` | 峰值随曝光升到某一档就不动了 | 会话的曝光上限把阶梯截短了，先核 `AO_DAHENG_MAX_EXPOSURE_MS` |

修好后重新点「开始」（勾着续跑），已完成的段会跳过。

## 5. 常见问题

**进度条一直停在 `块 0/112`。**
第一次进段前是 capture 与 fit（尤其"从零训练"），这两段不在时间估算里，几十秒到几分钟
是正常的。段状态表出现 `running` 之后就按块前进了。

**页面刚打开就提示"本目录里目前读到 N 段（计划 16 段）"。**
这是说明，不是错误：分母取计划，目录里暂时只有 N 段。

**某一行全是空白（不是 `—`）。**
表格里的空值就是空白（缺值按 `None` 交给表格，避免整张表序列化失败）；`—` 只出现在
文本摘要里。两者都表示"没测到"。

**换尺寸后进度条没变。**
总进度读的是"当前运行目录"；换尺寸后默认落盘目录也换了，旧目录的进度只出现在 ⑦。

**点了开始没反应。**
看按钮下面列的原因：红停项 / 黄项未勾 / 未连接 SLM / `bench_busy`（别的运算占着设备）/
本页已有一份在跑。

**停止之后又想跑。**
勾「从断点续跑」再点开始；它列出的"这次会跳过"就是不会重跑的段。想让某段重跑，需要换一个
新的 `--out`（或在 runner 侧手动清掉那个段目录）。
