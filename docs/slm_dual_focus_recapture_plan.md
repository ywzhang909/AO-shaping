# SLM 双光斑采集 — 焦点通道（daheng）重采集计划

**状态**: 计划草案 · **日期**: 2026-08-15 · **目标**: 恢复 focus (daheng) 通道的可用信息量

## 1. 根因诊断（基于现有 484 样本的实测证据）

### 1.1 两批数据的焦点相机行为完全不同

| 批次 | 样本数 | daheng 曝光 | daheng 帧实测 | 诊断 |
|---|---|---|---|---|
| 20260402_155508 | 100 | 20ms | **平场**：mean≈21, max≈30, 全帧 std≈1.1, 100% 非零 | 相机视野内**没有聚焦光斑**（散焦/未对准/均匀光） |
| 20260402_164456 | 51 | 20ms | **平场**：mean≈18, max≈30, 全帧 std≈1.1 | 同上，该批次焦点通道完全无信息 |
| 20260414_171241 | 333 | 30ms | **有光斑但饱和**：mean≈0.4, max=255（钳位）, 光斑 19–608 px, 质心 726–779 / 445–496 移动 | 光斑在视野内且对相位有响应，但 **MONO8 + 饱和** |

### 1.2 根因：`driver.py:172` 硬编码 `PixelFormat.set(MONO8)`

- `src/ao_shaping/drivers/ccd/daheng/driver.py` 第 171-172 行**强制 MONO8**（8-bit），尽管下游代码以 uint16 保存。
- 实测 0414 帧 `max` 恒等于 **255**（钳位），`p50(非零像素)=1.0` → 光斑亮核溢出、外围全为 ~0-2。
- 0414 光斑仅占帧 0.02–0.05%（300–600 px / 1.31M px）→ 256×256 缩采样后坍缩为几个像素的斑点。
- **推论**: 焦点通道并非"无光"，而是 (a) 动态范围被 MONO8 压到 8-bit，(b) 曝光使亮核饱和，(c) 光斑尺度太小失去 PSF 结构。
- 另一问题：0402 两个批次**视野内根本没有光斑** → 这两个批次的焦点通道不可用于训练（需重采或剔除）。

### 1.3 对回归任务的影响链

饱和 MONO8 光斑 → `normalize_per_image` 后亮像素→1.0、其余→0 → 焦点通道信息量≈光斑质心 → 模型对焦点通道学不到 PSF 形状信息 → 65 维 Zernike 回归只能靠 pupil 通道 → r2 天花板 +0.08。

## 2. 修复方案

### 2.1 相机配置（必须先做，采集前验证）

| 项 | 现配置 | 目标配置 | 修改点 |
|---|---|---|---|
| 像素格式 | `MONO8`（硬编码） | `MONO12` 或 `MONO16` | `driver.py:172`（需在主机硬件环境用 gxipy 实测相机支持的最高位深） |
| 曝光 | 20/30ms（固定） | 按**目标峰值亮度**自适应（见 2.3） | 采集脚本加 `--daheng-exposure` 调参 + 预检 |
| 增益 | `Gain.set(0.0)`（`driver.py:170`） | 保持 0，靠曝光控制 | 不变 |
| 光斑尺度 | 300–600 px | **放大光斑**（~5000–15000 px，PSF 含艾里环/像差结构） | 光学调整（相机物距/焦面位置），使 PSF 有可解析结构 |

> 修改 `driver.py` 需在装有 gxipy SDK 的采集机上进行（当前 venv 无 gxipy、`libs/` 下无 SDK）。建议新增 `pixel_format` 可配置参数（默认保持 MONO8 兼容现有流程，采集机显式指定 MONO12/16）。

### 2.2 光学对准预检（每次采集前必做）

1. SLM 加载**平场相位**（raw uint16 灰度，见 AGENTS.md 规则 1），检查 daheng 画面必须有清晰光斑。
2. `max` 应在**满量程 30–60%**（MONO12: 1200–2500; MONO16: 20000–40000），不得饱和、不得低于 8-bit 阈值。
3. 加载已知像差（如 defocus n=2/m=0, astigmatism n=2/m=±2），确认光斑发生可观测形变（扩张/拉长/出现艾里环）——证明焦点通道携带 PSF 信息。
4. 0402 平场问题排查：确认焦点相机靶面与成像面共轭（当前 0402 帧几乎无结构 = 靶面不在焦平面或视野无光）。

### 2.3 曝光/样本采集流程

```
1. 平场相位 → 采集一帧 → 读 max
2. 二分调整 exposure 直到 max ∈ [0.3, 0.6] × 满量程
3. 每 50 样本复查一次 max；若漂移（激光功率/偏振）超 20%，暂停并重调曝光
4. 全程记录 exposure 到 global_metadata.json（现有流程已支持）
```

建议在采集脚本中加一个 `--calibrate-exposure` 模式（先平场调曝光，再进入正式采集循环）。

## 3. 重采集规格

### 3.1 样本设计

| 参数 | 值 | 依据 |
|---|---|---|
| 相位模式 | `zernike`，`--n-max 10` | 与现有 65 维目标一致 |
| 系数范围 | `--max-coeff 3.0` | 与 0414（标签最干净，std≈1.73）一致；**不要用 0402 的 recovery 标签** |
| 目标样本数 | **500–800** | 0414 请求 500 实得 333；当前纯 0414 训练仅 331，多采提升信噪比 |
| 批次组织 | 1 个主批次 + 每 150 样本 1 个独立批次文件夹 | 便于按批次验证/回滚 |
| SLM 槽位 | `--memory-slot` 起始；脚本内已按 `(slot+i-1)%128+1` 轮转 | 规避 Santec 同槽 no-op（AGENTS.md 规则 2） |
| 间隔 | `--interval 0.5s`，等待 SLM 稳定 0.3s | 现有实现已含 |

### 3.2 验证门（采集后、训练前）

1. daheng：随机抽 20 样本，`max` 无饱和、光斑像素数 ∈ [3000, 30000]、质心随样本变化。
2. miicam：`mean ∈ [30, 150]`、有结构（std > 15），保持现状即可。
3. 标签：每样本 `metadata.json.phase_params.coefficients` 存在且 `n_max=10`（65 非活塞项）。
4. **快速回归冒烟**：用新批次单独训 `resnet18+pupil+combined` 各 60 epoch，看 val_mae 是否优于 expC 的 1.336（预期：两通道联合训练后 combined 显著优于 pupil-only，即焦点通道起了作用）。

### 3.3 数据落地

- 新批次放 `data/slm_dual_spot/<YYYYMMDD_HHMMSS>/`（现有 `slm_phase_capture.py` 自动命名）。
- 更新 `data/slm_dual_spot/README.md` 的规模表与批次说明（标注焦点通道已修复）。
- **0402 两批次的处理建议**：保留文件但训练时以 `--run-ids 20260414_171241,<新批次>` 排除；若想复用 pupil 侧，可后续单独做 pupil-only 消融。

## 5. 风险与权衡

- **MONO12/16 不可用或帧率下降**：退而求其次保持 MONO8 但把曝光调到"不饱和 + 光斑放大"也能恢复部分 PSF 信息（优先级低于位深修复）。
- **光斑放大依赖光学调整**：若无法动光路，可用 `--daheng-exposure` + 仅排除 0402 重跑 expC 基线，先确认 pupil-only 在纯 0414 + 新批次的增益。
- **采集机环境**：所有相机/SLM 改动需在硬件机执行（本 venv 无 gxipy / Santec SDK），脚本改动可在此仓库提交，硬件验证由现场完成。
