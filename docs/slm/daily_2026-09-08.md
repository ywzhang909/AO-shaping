### 2. Zernike 相位功能问题定位 (源码级)

两个用户报告的问题都定位到了根因:
1. **生成慢**: `generate_zernike_polynomial` 每次调用都新建 `ZernikeGenerator` +
   aotools `RZern(n_orders)` + `make_cart_grid` (整幅 1920x1200=2.3M px 网格) → 每次生成都是重头算。
2. **孔径半径无效**: `ZernikeGenerator.__init__` 构造坐标网格仅用
   `ddx=linspace(-1,1,width)`, `ddy=linspace(-1,1,height)*(h/w)`, `radius` 参数**从未参与网格构造**
   → 改孔径半径预览完全一样, 且默认"圆域"其实是把整幅面板映射进单位圆 (占满整个 SLM 面)。

### 3. 透镜相位接线问题定位

`multi_slm_controller.py` 的 "透镜" 分支:
- `像素间距 (um)` 与 `透镜半径 (像素)` 两个 `st.number_input` **都没设 `value=`**,
  Streamlit 会默认到 `min_value` (0.1 μm / 1 px), 不是硬件真实值 (8 μm / 600 px)。
- 应在连接后从 `st.session_state["slm{n}_pixel_pitch_um"]` / `_width` / `_height` 读取硬件默认。

### 5. Zernike 相位功能修复 (已完成, 源码级)

原派出的 subagent 超时未产出 (疑似导入 streamlit GUI 挂起)。已在主会话直接完成两个缺陷修复:

**D1 生成慢** → `src/ao_shaping/utils/zernike_calc.py`
- 新增模块级缓存 `_build_cached_grid(width, height, radius, n_orders)` (`functools.lru_cache`),
  复用 `RZern.make_cart_grid` 极坐标查表。
- `ZernikeGenerator.__init__` 从缓存取 `cart/xv/yv`, 不再每次重建。
- **实测**: 冷首次 2.77s → 二次缓存命中 **0.046s** (~60× 加速)。

**D2 孔径半径无效** → `zernike_calc.py`
- 根因: 旧网格 `ddx=linspace(-1,1,width)`, `ddy=linspace(-1,1,height)*(h/w)` (`radius` 未参与),
  且用 `scaler=h/w` 导致非方板 (1920×1200) 上单位圆是**椭圆**。
- 修复: 网格改为 `(pixel - center) / radius`, 单位圆 = 恰好 `radius` 像素, 真圆而非椭圆。
- **实测**: radius=600 vs 300 生成不同图案; 孔径非零像素 r600≈1.13M / r300≈283K (≈π r² 关系)。
- 语义修正: `mask` 单位圆内 = 孔径内; `radius=None` 默认 `min(w,h)//2` 行为不变。

**D3 透镜默认参数错误** → `multi_slm_controller.py` "透镜" 分支 (L381-402)
- `像素间距 (um)` / `透镜半径 (像素)` 原无 `value=` 默认到 `min_value` (0.1um / 1px)。
- 改为从 session_state 读硬件默认: `{prefix}_pixel_pitch_um` (8um), `min(width,height)//2` (600px),
  用户只需填焦距。

**连带修复 (本主会话发现):** `zernike_dm.py::generate_phase`
- 此前的网格使孔径铺满面板 (无 NaN 区); 网格修正后 1920×1200 面板 radius=600 时孔径外
  50% 像素为 NaN, 导致 uint16 cast 爆 RuntimeWarning + 垃圾值。
- 修复: `np.nan_to_num(phase_raw, nan=0.0, posinf=0.0, neginf=0.0)` (与
  `pattern_helper._zernike_to_uint16` 一致), 孔径外置 0。

**验证**: `test_zernike_calc.py` (29 passed, 新增 2 个回归测试覆盖 D1/D2),
`test_slm_pattern_helper.py`, `test_slm.py`, `test_slm_report.py` 共 48 passed;
`zernike_calc.py` + `zernike_dm.py` + `multi_slm_controller.py` 均 `py_compile` clean、
lsp_diagnostics 无 error。
> 注: `tests/ao_shaping/utils/test_display.py::TestZernikeCalibrationDisplayInstantiation`
> 失败是**环境问题** (ModuleNotFoundError: pygame), 与本次改动无关。

## 四、结论

今天两轮硬件探针给出**决定性诊断**: SLM 相位写入链路 (内存槽轮换、灰度生成、设备状态) 全部正常,
但 CCD 对相位无响应, 噪声底 ~0.58 下所有切换帧 rmse 仅 ~0.62 (~1.08×)。这与判别方法本身
(flat 复测对照组 rmse 同量级) 相互印证 —— 排除测量噪声干扰, 是**硬件/光路层面** SLM 调制未到达 CCD。
