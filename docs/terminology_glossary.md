## 0. 总则（先于任何具体词条）

1. **只改中文叙述**，不改代码。代码标识符（变量名、函数名、CLI 参数、类名、
   模块名、mermaid 节点标签、行内 `` `code` ``、围栏代码块）一律**原样保留**，
   即便其中含 `pupil`、`bench`、`实机` 等字样。
2. **英文叙述保留英文**。若某句上下文是纯英文（本地 ±40 字符窗口内无汉字），
   `pupil`、`bench` 等保留英文原词，不强行夹注中文。`bake-off` 自 2026-10-17
   起**不再保留英文**：中文叙述一律用**对比择优**（见 T-50），仅纯英文上下文
   仍保留 `bake-off`。
3. **首现夹注**。`pupil` 在中文叙述中**首次出现**时加一次中文
   释义（`pupil（瞳面）`），同段/同文档后续出现可省略
   夹注，但**不得**出现双重夹注（`（瞳面）（`）。
4. **不丢数据**。术语替换是纯措辞改写，任何数值、单位、公式、参数、路径、
   DOI、引用编号必须逐字节保留。改写后跑 §5 的守恒校验。
5. **新增词须登记**。若出现下表未覆盖的新口语词，先在本文档 §3 登记再替换，
   并在提交说明中注明，禁止私下引入同义词。

### 1.7 指标 / 分数（学术汇报、报告、论文通用）

> 以下词条是**定义登记**（非口语替换）：汇报与报告中这些符号必须带
> 定义使用，且同一指标全篇只允许一种中文名。

| 符号 | 规范名 | 定义 | 说明 |
|---|---|---|---|
| CV | **变异系数（CV）** | CV = std(I_T) / mean(I_T) | 目标区（目标掩码内）强度的变异系数，衡量均匀度；越小越好。 |
| EE | **能量效率（EE）** | EE = Σ(I_T) / Σ(I) | 目标掩码内能量占全帧比例；越大越好。 |
| PIB | **光斑完整性（PIB）** | 250×250 冻结窗口内能量占全帧比例 | 窗口按平场零级 (672,1027) 冻结；读数前先做「减中位数截断非负」，防止读出噪声负像素使 PIB 超过 1。 |
| composite | **复合分数** | composite = 0.6·EE + 0.4/(1+CV) | 闭环优化的标量目标函数（w_efficiency=0.6，w_uniformity=0.4）。 |

### 1.8 协议 / 流程术语（MIL 与闭环流程）

| 符号 | 规范名 | 定义 |
|---|---|---|
| 探针（probe） | **（随机）探针帧** | 向 SLM 加载特定相位后采集的一帧 CCD 实测；「强随机探针」= 相位标准差 σ≈4 rad 的随机探针，用于 Step A 重拟合（平场近似 δ 函数、像差不可辨识，必须用强随机探针）。 |
| 门控（gate） | **门控** | 以数值判据（如相关性 ≥ 0.5）决定是否放行下一步的硬约束；低于阈值即中止，不进入后续流程。 |
| 交错重放 | **交错重放（比较）** | 待比较的多个相位在同一会话、同一曝光下交替加载回放，以配对差作结论；用于剔除跨会话/跨时刻的功率漂移。 |
| 同帧（同帧验证） | **同帧（对比 / 核查）** | 模型预测与 CCD 实测取自**同一张** CCD 帧（同一时刻同一相位），对比时不引入跨时刻漂移。 |
| 热启动 | **热启动** | 用上一轮（或历史）拟合系数作为本轮初值继续优化。 |
| 双稳态 | **双稳态** | 同一设置下测量值稳定地分成两个不重合的簇（如 30 轮 GS 基线分为 25.7k/33.6k 两簇），提示光路存在两个稳定工作点。 |
| confirm-best | **confirm-best（最优复测）** | 每轮结束重测历史最优相位并以其为参考态，防止噪声把「假提升」写入参考态。 |
| 焦度 | **光焦度** | 菲涅尔焦度 1/f（m⁻¹）；「焦度扫描」= 菲涅尔焦度扫描。 |

### 1.9 A/B 对照语境术语

| 编号 | 口语 / 非规范（禁止） | 规范术语（必须） | 说明 |
|---|---|---|---|
| T-65 | 臂（A/B 对照语境：两臂 / 三臂 / 各臂 / 每臂 / 单臂 / A 臂 / B 臂 / 一臂） | **变体（variant）** | ML / MLOps 里同一个系统的两条 A/B 对照配置就叫 variant（变体）。仓库语境：`model_in_loop_hw_ab` campaign 的 `baseline_a` / `baseline_b` / `large_1000`、`sim_tue_methods` 的 `zernike_only` / `perpixel_only` / `joint`、前向模型架构对照的 `conv` / `mlp` 等，都是**同一命令的两种（多种）门槛/配置设定**。量词搭配：「两臂」→「两个变体」、「三臂对照」→「三个变体对照」、「各臂」→「各变体」、「每臂」→「每个变体」、「A 臂」→「变体 A」。 |

> **T-65 的例外（必须遵守）**：OOPAO 对比语境里的「臂」指的是 **numpy 路径与 OOPAO 路径
> 这两个并列的仿真后端分支**，**不是** A/B 对照的臂 → 一律写「**两个仿真后端分支** /
> **仿真后端分支**」（量词按语境取「两个 / 每个 / 某个 / 任一 / numpy / OOPAO /
> 2 个」）。**为什么不用「双后端 / 两后端 / 两个后端」**：那两个是**两个并列的仿真
> 后端分支**（两套彼此独立的实现：FFT 谱 Kolmogorov 路径 vs OOPAO `Atmosphere`
> 路径），**不是同一后端的两种配置**；「双后端」会被读成后者。涉及文件：
> `scripts/oopao/generate_oopao_vs_numpy_report.py`、
> `scripts/oopao/generate_oopao_impact_report.py`、
> `report/oopao_vs_numpy/oopao_vs_numpy_report/report.md`、
> `report/oopao_impact/oopao_impact_report/report.md`、
> `src/ao_shaping/drivers/sim/AGENTS.md`、`src/ao_shaping/drivers/sim/beam_backend.py`。
>
> **保留「后端」的地方**：指**路由机制本身**（后端开关 / 后端标志 / 后端路由 /
> 后端缓存 / 后端卫生 / 后端回归测试）与「与分支选择无关」（后端无关 / 后端不变）
> 时仍写「后端」—— 那是 code 层的概念（`beam_backend` / `_get_backend`），
> 不指那两个并列分支。
>
> **代码标识符不改**：`baseline_a` / `baseline_b` / `large_1000` / `arm` / `arms` /
> `ARM_LABEL` / `backend_arm` 等英文标识符，以及 `scripts/slm/model_in_loop_hw_ab.py`

> **非 A/B 语义**：「2f-Fourier 臂」原本指的是光路**配置**的分支，不套用「变体」，
> 改写为「**2f-Fourier 配置**」。
